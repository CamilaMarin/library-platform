## Rules

- The **domain layer** does not import anything from FastAPI, SQLAlchemy, or any framework.
- Controllers (interface layer) never access the database directly — they always go through a use case (application layer).
- Every external dependency is injected (Dependency Injection), never instantiated directly inside domain or use cases.
- Every infrastructure dependency is accessed through interfaces/protocols defined in the application layer (cloud agnostic — see `adr/0017`).
- Every new feature requires at least one domain test and one integration test for the endpoint.
- Prefer clarity over premature optimization.
- Do not add new libraries without justifying why stdlib or already-installed packages are insufficient.

## Style and linting

- Backend: PEP8 + Ruff.
- Frontend: ESLint + Prettier.

## Commits

- Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`).
- One commit = one coherent, reviewable change.

## API

- REST + JSON.
- OpenAPI auto-generated by FastAPI, always kept up to date (not documented separately by hand).
- Authentication: JWT custom (Access Token in header `Authorization: Bearer <token>`).

## Definition of Done (per feature)

- [ ] Meets the acceptance criteria from the corresponding spec in `.kiro/specs/`.
- [ ] Domain + integration tests passing.
- [ ] No direct infrastructure access outside its layer.
- [ ] If it touches personal data: registered in `DataProcessingRecord` and covered by the audit log.
- [ ] Documentation updated if the implementation revealed an unconsidered case.
- [ ] No cloud-provider-specific dependency introduced — all integrations behind abstractions.
